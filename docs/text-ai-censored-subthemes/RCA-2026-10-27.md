# Censored sub-themes prototype audit and RCA

## Finding

The feature was not removed from the live prototype. The supplied `/dashboards` page opens BI dashboards; the feature is under **TextAI → a TextAI dashboard → Settings → Theme configuration**. The McDonald's example remains at [dashboard 23](https://survey-re.vercel.app/text-ai/23), with its [Theme Configuration panel](https://survey-re.vercel.app/text-ai/23/theme-configuration).

Two later PRD requirements were incomplete:

1. Adding Food quality to a shown Censored response immediately retained both tags. There was no warning, Proceed or Cancel step.
2. Saved removals had response-tag assignments but no independent release marker or recoding guard. Recode only wrote history and incremented a counter, so it did not exercise protection against new automatic Censored assignments.

This is requirements-to-implementation drift, rather than a later rollback of the core feature.

## Evidence and cause

- `a0aae6f` (5 October) introduced the original implementation. `addCensoredAwareTags` allowed Censored plus ordinary tags when visibility was enabled. Its test explicitly expected two tags. That matched the initial request but became stale after the subsequent rule change.
- The retained PRD checkpoint, `outputs/textai-censored-prd/language-revision-2026-10-05/README.md` in the Work workspace, records adding confirmation and persistent manual-release rules to the native PRD. It explicitly records no prototype code changes in that document-editing turn.
- `22dbab6` (12 October) intentionally removed the dedicated censorship dashboard, metrics, banners and separate Outlier section, restoring the shared toolbar and widgets. That followed the owner's dashboard-alignment request and must not be reversed as feature recovery.
- Relevant source history contains no subsequent removal of Censored review, settings or taxonomy. Before repair, remote main was `689d522`; the three commits beyond the local checkout changed Survey finish-options and reward files, not TextAI.
- Live reproduction: hidden mode had eight ordinary responses and a compact four-hidden-response Review note. Shown mode filtered four Censored responses normally. Adding Food quality produced `Censored + Food quality`, without a dialog. Those edits were discarded and the original live visibility setting restored.

Tests protected the older multi-tag rule and did not cover the revised confirmation or recoding contract. The 12 October deployment also lacked browser verification because the approved extension was unavailable; its checkpoint disclosed that limit. This audit used the restored QuestionPro Chrome extension and exercised the browser flow.

## Repair

- Adding another sub-theme first warns that Censored will be removed, with the affected count for bulk actions. Cancel stages nothing. Proceed removes Censored and adds selected tags in the same pending edit; Save/Discard remains unchanged.
- Save records a response-scoped release marker alongside assignments and code frames. Older restaurant/shared-Outlier releases migrate without losing current tags.
- Full and custom Censored recoding exercise automatic Censored assignments through a release guard. Released responses cannot regain Censored; untouched Censored responses retain normal classification. This is a bounded prototype operation, not a production AI engine.
- Both settings routes retain their shared preference and a shorter description. Recode messaging explicitly states the manual-release exception.
- Ordinary widgets, Theme Configuration layout and protected system taxonomy remain intact.

## Verification

- All 70 TextAI tests pass, including mandatory confirmation, atomic replacement, persisted individual/bulk releases, repeated recoding, legacy migration, question isolation, Discard and invalid release metadata.
- TypeScript, targeted ESLint and the complete production build pass.
- Preview browser checks: Cancel creates no Save action; Proceed replaces Censored; Save/reload preserves release; full recoding retains Food quality without restoring Censored; visibility off shows the released response with three others hidden; filtered Select all releases all three, including records outside search; Save/reload/custom-Censored recoding retains all releases; empty Censored stays reviewable; both settings routes synchronize.
- McDonald's still uses the same ten default widget IDs. No special censorship dashboard or banner was reintroduced.
- Evidence is under `outputs/censored-feature-audit-2026-10-27` in Work. Deployment and post-deployment results are recorded in its audit checkpoint.

## Prevention

Use the behavioral checklist as the completion contract for PRD revisions and prototype changes. Retain the new confirmation and recoding regression tests. Verify deployed interactions through the approved browser before declaring completion; build/deployment success alone does not establish interaction behavior.
