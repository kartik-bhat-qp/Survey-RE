## Requirement

Add **⋮ → Settings** to every Text AI widget, using BI's right-side settings drawer and enlarged widget preview. Reuse existing BI controls, labels, defaults and interaction patterns wherever their meaning matches. An entire BI settings set is not a verified one-to-one match for any of the nine widgets: reuse compatible controls and adapt the analytical sections below.

## Shared behavior and acceptance

- **General:** widget name/show name and BI filter scope: Dashboard, Widget, Combined (AND), None. Apply to analyzed responses only. Show only controls supported by that widget; source selection remains in the existing add/edit flow.
- **Analytics / Labels / Columns:** show relevant tabs only. Top N/manual selection limits displayed categories after filtering and sorting; it does not change the denominator or coding. Keep existing prototype custom-selection behavior where already supported.
- **Design:** inherit dashboard design by default; allow widget overrides for theme, typography, palette and legend/label presentation as applicable. Sentiment colors stay bound to the same six category identities across widgets.
- **Defaults:** opening Settings changes nothing; existing widgets retain their current appearance/calculations. New presentation controls initially preserve current behavior. No automatic weighting, recoding, processing or summary regeneration.
- **Persistence:** follow BI's immediate-save interaction; reflect valid edits in the preview and widget, report save failures, and preserve the last saved value on failure. Scope settings to dashboard + widget; reload and supported duplicate/copy flows retain them independently. Reset restores widget defaults/dashboard design inheritance. Prototype persistence is browser-local.
- **Data correctness:** disclose the actual base and distinguish responses from mentions/assignments. Never sum overlapping sub-themes as unique respondents or silently renormalize percentages after hiding categories. Empty results show a clear no-data state. Formatting affects supported exports/shared rendering consistently; viewers cannot edit settings.
- **Done:** all nine widgets have working relevant controls, persistence and reset; changes stay isolated to the edited widget; filtering, hierarchy, drill-down, defaults and existing prototype interactions remain intact. Validate empty/multi-tag data, invalid ranges, reload and dashboard-design inheritance.
